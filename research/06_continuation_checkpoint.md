### 4.1 What the ChatGPT track is responsible for

The ChatGPT research track handles evidence from sources that GitHub does not cover:
1. **YouTube professional content** — Creator education channels, screenwriting tutorials, production methodology videos
2. **Professional web sources** — Screenwriting blogs, craft publications, style guides not on GitHub
3. **Academic sources** — Peer-reviewed research on narrative cognition, listening comprehension, audience engagement
4. **Professional craft books** — McKee, Field, Goldman, Snyder, Truby (primary sources for derivative GitHub skills)

### 4.2 Priority research requests (ranked)

1. **Screenwriting format and conventions** — The archive has beat sheets but no screenplay format guidance. Need: slug lines, action line conventions, dialogue formatting, V.O./O.S., montage, intercut, industry page-per-minute norms. Sources: Syd Field *Screenplay*, Robert McKee *Story*, professional screenplay format guides.

2. **Spoken rhythm and audio-first writing** — The archive identifies that readability formulas don't apply to listening (F-190) but offers no positive alternative. Need: techniques for writing to spoken rhythm, breath-length calibration, phonetic flow, signposting for listeners. Sources: broadcast journalism guides, audiobook narration craft, podcast production guides.

3. **Retention hook timing validation** — S58 claims 60–90 second retention hooks but provides no evidence. Need: YouTube analytics studies, A/B testing data, attention span research for video content.

4. **CLT modality effect for video** — S45 extrapolates classroom research to video scripts. Need: studies specifically testing modality effect in video/narration contexts.

5. **Podcast script structure** — Zero coverage in archive. Need: episode structures for interview, solo narration, multi-host, and serialized podcast formats.

6. **Commercial/advertising scripts** — Zero coverage. Need: 15/30/60-second spot structures, brand voice integration, CTA craft.

7. **Humor writing methodology** — Only comedy genre pack (S01) with basic setup/subversion. Need: systematic comedic timing, callback structure, running gag mechanics.

8. **Non-English scriptwriting traditions** — 61 of 63 sources are English-primary. Need: scriptwriting conventions from other languages and cultural traditions.

9. **Classic craft book primary source validation** — Verify that GitHub skills (S01, S02, S55) accurately represent McKee, Swain, Snyder, Truby, and other cited authorities. Check for distortion or oversimplification.

10. **Emotional arc design** — Cross-format gap. Need: audience emotional trajectory design (not character arc, but audience experience arc).

## 5. Architecture Notes for Future Skill Builder

These observations may guide whoever eventually builds the SKILL.md (which this research phase does NOT produce):

1. **Conditional routing is essential.** Only 25% of findings are universal. The skill must detect format, category, and genre before applying specific knowledge.

2. **Framework selection, not prescription.** Multiple valid structure frameworks exist. The skill should help users choose, not dictate.

3. **Evidence hierarchy must be visible.** Users should know whether advice comes from empirical research, cross-source consensus, or single-practitioner opinion.

4. **The listening gap is real.** All readability metrics are for reading, not listening. The skill needs either a) validated listening metrics (if found by ChatGPT track) or b) explicit caveats on every readability recommendation.

5. **Anti-AI awareness is craft, not detection.** The 26 anti-patterns (S14) and 9 structural failure modes (S02) are tools for self-improvement, not automated detectors.

6. **Derivative chains must be transparent.** When the skill cites scene/sequel or Save the Cat, it should acknowledge the original author (Swain, Snyder), not present the GitHub skill as the primary source.

7. **Fiction and nonfiction verification differ fundamentally.** Fiction requires internal consistency checking (adapted from FActScore). Nonfiction requires external fact verification (S26/S27/S25 methodology). The skill must route appropriately.

8. **Localization is not translation.** S56's meaning-based approach and fluency test suggest the skill should support multilingual output through adaptation, not word-for-word translation.
